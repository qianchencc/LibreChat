# Domain language

- **Agent run envelope**: the versioned, JSON-safe request contract created after ingress authentication and protocol validation but before agent, provider, tool, or MCP initialization. It carries only the validated protocol payload and the minimum trusted principal identifiers. The execution host rehydrates all runtime state from those identifiers.
- **MCP runtime request body**: trusted chat identifiers supplied only while an MCP server handles an agent request. It enables request-scoped header placeholders without retaining user-specific request data on a shared server definition.
- **Subagent thread**: a durable, view-only child conversation owned by one parent conversation and subagent identity. A parent agent may continue it by stable `threadId`; each continuation uses a fresh execution lease restored from the canonical child transcript. It is not an ordinary human-writable chat.
- **Live subagent task owner**: the one API process holding a detached child execution, its abort controller, and its bounded control queue. Redis may route trusted poll/control envelopes to that owner, but it does not migrate or persist the executor; Mongo persists only the logical child thread and its continuation fence.
- **Subagent completion wakeup**: a durable internal `continue` trigger pre-registered before detached child execution so a process crash cannot lose the wakeup. Delivery defers until the child's terminal transcript is persisted, targets the initiating agent and exact parent response branch, carries task metadata rather than child output, waits for the parent generation to settle, and starts the parent turn that collects the result through the existing task store.
- **Theme definition**: a versioned, data-only description of LibreChat semantic colors and shared appearance roles, optionally specialized by light or dark mode. The theme module validates and resolves partial definitions against bundled defaults before adapters apply them. A theme definition does not contain arbitrary CSS, application behavior, or alternate feature layouts.
- **User file**: a private, durable asset uploaded by or persistently generated for exactly one user. Conversations, Agents, Projects, maintained documents, and Artifact content may reference a user file, but do not become its owner. A temporary sandbox file is not a user file.
- **Maintained document**: Markdown content that a user and Agent continue editing and viewing inside LibreChat across turns and sessions. Standalone exports and public shares are separate representations.
- **Attachment reference**: a durable link from a maintained document to a user file's LibreChat identity. It is neither a physical storage location nor an access grant.
- **File projection**: a derived representation of a user file for a provider, code runtime, or export. A projection may be temporary and replaceable without changing the user file's identity.
- **Active file context**: the bounded set of user files explicitly made available to an Agent for the current conversation or resource. A user's wider file library is discoverable on demand but is not implicitly included.
- **Attachment access**: permission to read a referenced user file, evaluated for the requesting principal each time content is retrieved. Possessing an attachment reference does not confer attachment access.
- **Deleted user file**: a user file that is immediately unavailable for new reads but remains recoverable during a retention period. Its attachment references remain intact and resolve to an unavailable state unless the file is restored.
- **Share snapshot**: an immutable public representation of a maintained document and only the user files it referenced when published. It does not retain live access to the owner's files.
- **Collaborator file access**: revocable permission to read a live user file inherited from an explicitly shared Conversation or Project within the same tenant. It does not transfer file ownership.
- **File version**: an immutable user file identity for one exact content revision. Replacing content creates a new file version and does not silently retarget existing attachment references.
- **Markdown package**: a standalone export containing Markdown plus referenced binaries under relative asset paths. It is distinct from the private maintained document and its live attachment references.
- **Artifact content**: message-bound HTML or React source that LibreChat renders in its Artifact preview. It may reference user files, but it is not a standalone website, project directory, or file owner.
- **Artifact attachment reference**: a durable link from Artifact content to a user file's LibreChat identity. At render time it becomes a safe preview or download projection appropriate to the file type; it is not a storage URL and does not imply that every attachment type can render inline.
- **Artifact attachment presentation**: the observable representation of an Artifact attachment reference. LibreChat renders supported formats inline and otherwise presents stable file metadata with a download action.
