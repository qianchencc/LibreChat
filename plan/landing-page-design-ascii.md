# LibreChat Landing 页面设计与表达分镜

## 设计判断

Reading this as: 面向首次接触 LibreChat 用户的公开 SaaS Landing，使用克制、可信、
产品实录优先的视觉语言，延续 LibreChat 现有主题系统，并借鉴 Recordly 的滚动叙事。

- `DESIGN_VARIANCE: 7`
- `MOTION_INTENSITY: 6`
- `VISUAL_DENSITY: 4`
- 模式：现有产品的品牌延展，不重做应用内信息架构
- 设计基础：`@librechat/client` 组件、现有语义主题角色、Tailwind、Framer Motion
- 字体：沿用主题字体，不为 Landing 单独引入字体
- 图标：沿用项目已有 Lucide 图标，不混入第二套图标家族
- 色彩：页面跟随现有亮色或暗色主题，所有区块保持同一模式，只使用现有强调色
- 形状：控件使用主题 control radius，媒体和叙事面板使用主题 surface radius

## 页面要表达的唯一故事

用户不需要先理解模型、Provider、Tool 或 Artifact 的术语。页面只讲一个闭环：

```text
按提示完成 API 密钥配置
          |
          v
选择适合任务的智能体
          |
          v
给出目标，并附上材料
          |
          v
智能体调用搜索、工具和 Skill
          |
          v
得到可检查、可修改、可分享的成果
```

Landing 负责介绍和最短教程。完整操作说明仍由 `/help` 承担。

## 页面文案

### Hero

- H1：`LibreChat`
- 主张：`你的 AI 工作台`
- 说明：`在一个工作台里对话、检索、处理附件，并交付可继续编辑的成果。`
- 未登录主按钮：`开始使用`
- 已登录主按钮：`进入工作台`
- 次按钮：`查看工作方式`

### 工作方式

- 标题：`从一个任务，到可以使用的成果`
- 选择智能体：`按任务选择智能体，不必先理解每个模型的差异。`
- 给出目标和材料：`上传附件，启用联网搜索或 Skill，让它完成完整过程。`
- 检查并分享：`结果可以成为网页、报告或文件，继续修改后直接分享。`

### 能力摘要

- `直接对话`：在同一个界面切换模型和智能体。
- `理解附件`：把图片、文档和其他附件放进任务上下文。
- `调用工具和 Skill`：让智能体完成检索、处理和外部操作。
- `制作 Artifact`：生成网页、报告和文件，并继续预览或修改。

### 帮助入口

- 标题：`第一次使用，也不必自己摸索`
- 说明：`这里展示最短路径，完整说明和操作演示放在帮助页。`
- 按钮：`查看帮助`

## Recordly 动效逆向结论

Recordly 首页并未使用 GSAP。页面由 Framer 发布，运行时加载 Framer Motion：

- `window.gsap` 和 `window.ScrollTrigger` 均不存在。
- 页面加载 `motion.mhpWI3bl.mjs`，没有 GSAP bundle。
- 首屏入场为 `opacity: 0.001 -> 1`、`y: 40px -> 0`。
- 首屏 tween 延迟 `0.2s`，持续 `1s`，ease 为 `[0.12, 0.23, 0.17, 0.99]`。
- 功能面板为原生 CSS `position: sticky`，桌面端 `top: 128px`、高度 `400px`、间距
  `64px`、圆角 `12px`。
- 功能面板约有一半进入视口后执行同类 40px 上移淡入，实测约 `1s` 完成。
- 下一张面板接近时，上一张面板由 `scale(1)` 到 `scale(0.98)`，同时向上移动
  `0 -> -16px`。滚动反向时变换也会反向，没有固定时间轴。
- 桌面端三个面板在 `top: 128px` 叠放。小于 `810px` 时 sticky 被取消，改为单列。
- 导航外层为 `position: fixed`，高度 `76px`，层级 `z-index: 5`。
- 视频使用 `muted`、`loop`、`playsinline` 和 `preload="none"`。进入相关视口后播放，
  离开后暂停。
- 页面包含 Lenis `1.1.9`，但未启用 `lenis-smooth` class。核心叙事并不依赖自定义
  平滑滚动。
- FAQ 仅做约 `240ms` 的快速 opacity reveal。

Recordly 的实现缺陷也需要规避：

- 第一段功能视频使用 MOV，Chromium 中出现过空白。
- 功能视频没有 poster，懒加载前是纯空区域。
- 完整页面截图会因为视口触发和视频懒加载留下大块空白。
- 只有第二张 sticky 面板有明显后退变换，三张面板的运动规则不完全一致。

## 我们采用的动效规格

不新增 GSAP。仓库已有 `framer-motion@12.40.0`，Recordly 本身也使用 Motion。现阶段
CSS sticky 加 Motion 已能完成目标，引入 GSAP 只会增加依赖和两套动画生命周期。

### 页面加载

- 导航直接出现，不移动。
- Hero 文案：`opacity 0 -> 1`、`y 20px -> 0`、`500ms`。
- Hero 视频：`opacity 0 -> 1`、`scale 0.985 -> 1`、`700ms`，比文案晚 `100ms`。
- 使用缓出 tween `[0.16, 1, 0.3, 1]`。非手势入场不需要弹性。

### 用户操作

- 按钮在 pointer-down 时立即缩放到 `0.98`，释放后使用无回弹 spring 回到 `1`。
- 建议 spring：`bounce: 0`、`duration: 0.3s`。
- 所有链接保留清晰 focus ring，不用磁吸按钮和自定义光标。

### Sticky 工作方式

- 只在 `min-width: 768px` 启用。
- 使用 CSS `position: sticky`，不 pin 整个页面，不接管滚轮。
- 推荐 sticky top：导航高度加 `24px`。
- 下一面板进入时，上一面板按滚动进度直接映射：

```text
scale:   1.000 -> 0.965
y:       0px   -> -16px
opacity: 1.000 -> 0.78
```

- 变换只使用 `transform` 和 `opacity`。
- 映射来自 Motion `useScroll` 和 `useTransform`，滚动反向时自然反向，不使用离散触发。
- 不加入 bounce。滚动本身已经提供速度和方向，额外回弹会破坏直接操控感。

### 视频

- Hero：`preload="metadata"`，其余视频：`preload="none"`。
- 所有视频使用准备好的 WebP poster，预留稳定 `16:9` 尺寸。
- `IntersectionObserver` 在视频主要部分进入视口时播放，离开时暂停。
- 默认 `muted loop playsInline`，不自动制造声音。
- `prefers-reduced-motion: reduce` 时不自动播放，显示 poster 和播放按钮。

### 普通内容入场

- 能力摘要只做一次 `opacity 0 -> 1`、`y 16px -> 0`，持续 `400-500ms`。
- 最多使用 `60ms` 的短 stagger，仅用于说明阅读顺序。
- FAQ 或 Help CTA 不做 3D 翻转、视差或缩放。

### 无障碍和降级

- Reduced motion：取消 sticky 缩放和位移，面板按正常文档流展示，内容使用短 cross-fade。
- Reduced transparency：固定导航改为不透明主题表面，不使用 backdrop blur。
- More contrast：使用主题的高对比边框和文字角色。
- 移动端始终使用自然滚动，不使用 Lenis、横向滚动劫持或整页 pin。

## 实现边界

- Landing 不复制 `/help` 的完整步骤，只展示四段最短操作。
- Landing 和 `/help` 共享内容 ID、标题和媒体元数据，避免两份文案漂移。
- 不增加 GSAP、Lenis、字体或第二套图标依赖。
- 不制作假的产品界面，不使用渐变球、装饰光晕、跑马灯或滚动提示。
- 页面不出现用户附件、私有 S3 地址或需要认证才能加载的媒体。
